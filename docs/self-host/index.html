Container Usage#

The application can run without copying config.yaml into the container. If no config file exists, it will automatically create one with sensible defaults.

Environment Variable Support#

Soulsolid supports environment variables in configuration files using the !env_var tag:

Secrets can also be loaded from a file (handy for Docker/Kubernetes secrets) with the !env_file tag: the named environment variable holds the path to the file, and the file’s contents become the value. See Configuration for details.

The application will fail to start if a referenced environment variable is not set.

Podman / Docker#

The web interface will be available at http://localhost:3535.

The container works from /app, so the generated default config stores the library in /app/music, downloads in /app/downloads and job logs in /app/logs/jobs. The database defaults to /app/library.db; to keep it on the ./data volume, set database.path: /data/library.db in config/config.yaml.

Logs#

Soulsolid logs to the container’s output, so podman logs soulsolid (or docker logs soulsolid) shows what it’s doing. Each background job also writes its own log, by default under /app/logs/jobs, which you can read from the Jobs section of the app. See Logging.

Health check#

GET /health returns OK while Soulsolid is running, for container health checks or Kubernetes probes. See Hosting.

Want to run Soulsolid from source or contribute? See the Development section of the README and the contributing guide.
